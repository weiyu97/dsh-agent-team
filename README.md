# dsh-agent-team · 多桌面 agent 接入插件

> 给 [dsh](https://github.com/) 的一个本地插件：在设置页里统一登记局域网内的多个桌面 AI agent，显示接入方法、分配岗位、用一次性配对码确认接入、并在服务端诚实探活。**只做接入管理和诚实探活，不自动派活、不自动回信、不恢复全局轮询。**

写给想在自己机器上，把散落在局域网里的几个 agent（MCP 服务、文件板 worker、人工接入的窗口）收进一个面板统一看状态的人。

## 它解决什么

- **一眼看清谁接了、是什么岗位、连不连得上。**
- **省事接入**：给对端一段「接入提示词」，它按模板回报一段，你整段粘进设置页就自动填表。
- **一次性配对码**：服务端生成、只存 hash、5 分钟过期、错码/重放都拒；通过才标记「已验证」。
- **诚实探活**：MCP 端点直接打 `report()`；`doing.started_at` 卡超过 10 分钟判「假在线」，其余端点如实标「需人工核对」。**不把 TCP 通当已唤醒。**

## 能力边界（先读，别期待错）

这个插件是**管理面**，不是执行体。它做不到「凭空叫醒一个没在跑的窗口」，也不替 agent 干活。它能如实告诉你：连不连得上、任务队列里有没有卡住的活。真正的自动执行，取决于对端有没有常驻执行体——那是另一件事。具体怎么搭，见 docs/05-从接入到自动执行-部署实操.md（外部实操记录，非插件能力）。

## 环境要求

- 一个跑得起来的 dsh（`dsh web` 能开、能在浏览器进设置页）。
- **Node ≥ 18**（插件用 ESM、`node:crypto`、`fetch`）。
- 探活只支持 MCP streamable-http 端点；文件板/人工接入只登记，不 HTTP 探活。

### 可选：共享信箱功能要的 SSH 工具（作者点名要写清）

只有在你想用「共享信箱」（多台机器共用一块文件板）时，才需要这些。**纯登记录入 + MCP 探活不需要任何 SSH。**

- **本地要有 `ssh` 和 `scp`**（OpenSSH 客户端）。
  - Debian/Ubuntu：`sudo apt install -y openssh-client`
  - RHEL/CentOS/Fedora：`sudo dnf install -y openssh-clients`
  - macOS：系统自带。
- **要能对共享信箱所在的机器做非交互 SSH 登录**，因此需要一个 `sshpass`（用来喂密码）：
  - Debian/Ubuntu：`sudo apt install -y sshpass`
  - RHEL/CentOS/Fedora：`sudo dnf install -y sshpass`
  - macOS：`brew install hudochenkov/sshpass/sshpass`
  - 若你用的是 SSH 密钥而非密码，可以不要 `sshpass`，但当前版本的健康检查走的是密码路径。
- **SSH 账号密码从哪来、放哪**：见 `docs/01-安装与前置.md`。一句话——你自备一台能 SSH 的 Linux/NAS 主机（放文件板的），把登录密码写进插件数据目录下的 `mailbox.env`，权限设成 `600`，界面和日志都不会回显它。
- **需要哪些操作权限**：那个被 SSH 的账号，需要对文件板根目录有 **读写 + 建目录** 的权限（插件会 `ls` 检测六个子目录、缺的 `mkdir -p` 建）。不需要 root，一个对目标目录有写权限的普通账号即可。

## 安装

插件以 dsh bundle 形式分发（`@local/dsh-agent-team`）。

1. 把本仓库的 `bundle/` 目录放到 dsh 能加载的插件位置（或按你 dsh 版本的 `install_bundle` / `plugin_manager` 用法装入 `web` profile）。
2. 启用插件，重启 dsh 的 web 服务（或按 dsh 版本热重载）。
3. 打开设置页，侧栏应出现「Agent 接入」一栏。

装好怎么验证、以及具体命令，见 `docs/01-安装与前置.md`。

## 快速开始（五分钟接一个 agent）

1. 打开「设置 → Agent 接入」。
2. 点「添加」，填 `agent_id`（唯一名）、显示名；接入方式选 `mcp-http`（对端起了 MCP 服务）或 `人工`（你自己抄码）。
3. 保存。点该行的「配对」，生成一次性配对码。
4. 把这一整段「接入提示词」复制，发给对端那个 agent。它按模板回报一段。
5. 把那整段回报粘进设置页任意输入框，自动填表。
6. 核对对方回报的配对码对上，点「确认接入」。
7. 点「刷新」，看状态。`可达 / 假在线 / 停摆 / 需鉴权 / 需人工`——只报真实探活。

详细动线与每个按钮干什么，见 `docs/02-使用与配置.md`。

## 安全模型（别退化）

- **所有校验在 Host**：`agent_id`、`transport`、`role`、端点协议与私有网段，全在服务端强校；客户端校验只是 UX。
- **信任字段服务端独占**：`verified / verified_at / fingerprint / pairing_id` 客户端 POST 带任一即 400；改身份或端点自动撤销 `verified`。
- **配对码真比对**：服务端存 sha256 hash + 过期 + 一次性；客户端只拿展示串。
- **凭据不回显**：Bearer token、SSH 密码只落本机文件、`600` 权限，只回 `has` 不回值。
- **只接受 loopback**：HTTP 路由只对本机回环开放，跨机访问请走可信反代。

已知局限与未验证项，如实列在 `docs/04-安全模型与已知局限.md`。

## 补充：想让它真正自动执行？

本插件只负责「接入 + 诚实探活」，不含派活与自动执行。若要把接入的 agent 真正驱动起来跑活（自动领任务、调用对端模型生成、产出回传共享板），见 [docs/05-从接入到自动执行-部署实操.md](docs/05-从接入到自动执行-部署实操.md)——真实跑通的部署方法与踩坑记录，属外部实操、非插件核心功能。
