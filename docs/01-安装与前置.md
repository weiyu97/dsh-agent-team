# 01 · 安装与前置

> 这份讲三件事：怎么把它装进 dsh、共享信箱要的 SSH 工具怎么准备、账号密码从哪来、需要什么权限。

## 一、装插件

dsh 的插件以 bundle 形式加载。假设你的 dsh 用 `web` profile：

1. 把本仓库的 `bundle/` 目录，整份复制到 dsh 的插件目录（具体路径随你的 dsh 安装方式而定，通常是 profile 的 `node_modules` 或插件源目录）。
2. 在 dsh 里启用这个 bundle（按你的 dsh 版本用 `install_bundle` 或 `plugin_manager`，目标名 `@local/dsh-agent-team`）。
3. 重启 dsh 的 web 服务。

> 不同 dsh 版本的安装命令不完全一样。如果你的版本有 `plugin_manager`，装完记得「先 disable 再 enable」触发重载——对已启用的行只 `enabled=true` 不会重载。

## 二、验证装好了

- 打开 dsh 设置页，侧栏能看到「Agent 接入」。
- 页面能正常载入（不报「载入失败」）。
- 点「添加」能弹出表单，保存后能看到一行。

看到这三样，说明 Host 路由和 Client 面板都起来了。

## 三、共享信箱要的 SSH 工具（可选）

**不用共享信箱就跳过这节。** 纯登记 + MCP 探活不需要任何 SSH。

共享信箱 = 多台机器共用一块文件板（某台机器上的一个目录，下面有六个固定子目录：消息 / 回执 / 状态 / 附件 / 任务 / 产出）。插件通过 SSH 连到那台机器，检测并创建这六个目录。

### 3.1 装 SSH 客户端和 sshpass

| 系统 | 命令 |
|---|---|
| Debian / Ubuntu | `sudo apt install -y openssh-client sshpass` |
| RHEL / CentOS / Fedora | `sudo dnf install -y openssh-clients sshpass` |
| macOS | 自带 ssh；`brew install hudochenkov/sshpass/sshpass` |

- `ssh` / `scp`：登录和传文件用。
- `sshpass`：把密码喂给 ssh，实现免交互登录。走 SSH 密钥的场景可以不用它，但当前版本的健康检查用密码路径。

### 3.2 准备一台放文件板的主机

你需要一台能被 SSH 的 Linux/NAS 主机来放文件板（软路由、NAS、树莓派、随便一台常开的 Linux 都行）。要点：

- 开了 `sshd`（22 端口）。
- 有一个能登录的账号（`user@内网IP`）。
- 这个账号对文件板根目录有 **读写 + 建目录** 权限。不需要 root；一个对目标目录有写权限的普通账号就够。

创建板子根目录（在目标主机上执行）：

```bash
sudo mkdir -p /srv/agent-board
sudo chown <你的账号>:<你的账号组> /srv/agent-board
```

六个子目录插件会自己建（或你手动建）：

```bash
mkdir -p /srv/agent-board/{消息,回执,状态,附件,任务,产出}
```

### 3.3 账号密码放在哪（重要，别搞错）

插件不会让你在界面里填 SSH 密码，也不回显它。密码只放本机一个文件：

1. 找到插件的本地数据目录（插件运行时会用到它，通常是 dsh 的 profile 数据目录下、本插件专属的那个文件夹）。
2. 在里面建一个 `mailbox.env`，内容一行：

```
LAN_SSH_PASS=你的SSH登录密码
```

3. 权限设成只有你自己能读：

```bash
chmod 600 mailbox.env
```

- 密码只用于 `sshpass` 喂给 ssh，不进界面、不进日志、不回显。
- 换密码就改这个文件，重启 dsh web 服务生效。
- **绝不**把密码写进任何会被提交到 git 的文件里。仓库里的 `.gitignore` 已经挡住了 `mailbox.env`。

### 3.4 页面里怎么填

在「共享信箱」区：

- 「在哪台机器」选 `外地（远程）`。
- 「主机」填 `user@内网IP`（如 `user@192.168.1.100`）。
- 「根路径」填板子的绝对路径（如 `/srv/agent-board`）。
- 保存 → 点「重新检测」看六个目录在不在 → 缺的点「一键补齐」。

> 本机模式（文件板就在 dsh 这台主机上）不需要 SSH，直接用 `bash` 读写。

## 四、需要哪些权限（汇总）

| 功能 | 要什么权限 |
|---|---|
| 登记 + MCP 探活 | 无额外要求。只需 dsh 本身能读自己的状态文件。 |
| 共享信箱（远程） | 一个能对板子根目录读写+建目录的 SSH 账号；密码放本机 `mailbox.env`（600）。 |
| 共享信箱（本机） | 运行 dsh 的系统用户对板子目录有读写权限。 |

不需要：root、不需要改系统配置、不需要动被管理 agent 的机器。

## 五、停用 / 卸载 / 数据

- 停用：在 dsh 里把插件 `enabled=false`。
- 卸载：删掉 bundle 目录，`plugin_manager remove_bundle`（如果你用了它）。
- 数据清空：删插件数据目录下的 `registry.json` 与 `pairs.json` 即可，无副作用（都是可重建的本地状态）；`tokens.json`、`mailbox.env` 删掉等于清空已存凭据。
