# 02 · 使用与配置

> 逐个按钮讲清楚：界面每一栏填什么、每个按钮干什么、什么状态下该做什么。

## 界面分三块

1. **共享信箱**：所有 agent 共用的文件板地址（可选）。
2. **agent 列表**：已登记谁、什么岗位、当前状态。
3. **编辑表单 / 配对卡片**：点「添加」或「编辑」后出现。

## 一、共享信箱区

| 字段 | 填什么 | 说明 |
|---|---|---|
| 在哪台机器 | 本机 / 外地 | 本机 = 文件板就在 dsh 这台主机；外地 = 另一台机器，走 SSH |
| 主机 | `user@内网IP` | 外地才填。如 `user@192.168.1.100` |
| 根路径 | 绝对路径 | 板子根目录，如 `/srv/agent-board`。六个子目录名固定，只改根路径 |

按钮：

- **保存地址**：把上面三栏存进本地 `mailbox.json`。
- **重新检测**：按已保存的地址去 `ls`，列出六个子目录哪些在、哪些缺。**先保存，再检测**——检测读的是已保存的配置。
- **一键补齐**：把缺的子目录 `mkdir` 建出来，建完再验一遍。

> 本机模式不依赖 SSH；外地模式要先把密码写进 `mailbox.env`（见 `01-安装与前置.md`）。读不到密码时这里会如实报「连不上板子」，不会假装成功。

## 二、agent 列表

每行显示：显示名、`✓`（已验证）、接入方式、岗位、状态、操作按钮。

状态含义（**只报真实探活**）：

| 状态 | 含义 |
|---|---|
| 可达 | 连得上，且 `report()` 里没有卡住的 doing |
| 假在线 | 连得上，但 `doing.started_at` 卡超过 10 分钟（服务在、活没动） |
| 停摆 | 连不上 |
| 需鉴权 | 端点返回 401/403，要 Bearer token |
| 需人工 | 非 MCP 端点，或端点非法，只能人工核对 |
| 未探 | 还没点刷新 |

操作：

- **编辑**：改显示名/端点/岗位/备注。
- **配对**：生成一次性配对码。
- **撤销验证**（已验证的行）：把 `verified` 清掉、作废配对码。
- **删除**：删掉这个 agent。

## 三、编辑表单

| 字段 | 填什么 | 备注 |
|---|---|---|
| agent_id | 唯一名，字母数字下划线连字符，≤32 | 必填。要和板子上的 `状态/<id>.json` 对上 |
| 显示名 | 界面显示的名字，中文也行 | 随便起 |
| 接入方式 | mcp-http / file-board / webhook / manual | mcp-http = 对端有 MCP server；file-board = 共享目录；manual = 你自己抄码 |
| 岗位 | dispatcher / adjudicator / reviewer / executor / runner | 空 = 不派活 |
| 端点 | `http://ip:port/mcp` 或板子绝对路径 | mcp-http 必填完整 URL，只收内网私有 IP、`/mcp` 结尾 |
| 备注 | 给自己看 | 随便写 |
| Bearer token | 对方 MCP 开了鉴权才填 | 只存本机 `tokens.json`（600），不回显 |

**省事接入**：表单顶部有个大文本框——把对方 agent 回报的那一整段文字粘进去，点「识别并填入」，自动把字段填好（只填空的、不覆盖你已填的）。也可以直接把整段粘到任意字段里，会自动识别。

**提示词**：表单底部有「复制提示词」，点一下把包含回报模板 + 配对码的整段复制下来，发给对方 agent。

## 四、配对流程

1. 点某行的「配对」→ 服务端生成一次性码（5 组、5 分钟过期）。
2. 页面上出现配对卡片，带码和提示词。
3. 把提示词（含码）发给对方。
4. 对方按模板回报，把整段粘回设置页自动填表。
5. **你核对对方回报的码和你这边显示的一致**，点「确认接入」→ 该 agent 标记「已验证」。
6. 切换页面这码不会丢（存在浏览器会话里）。

> 配对码的语义是「人事确认」：证明你确认过对方回报了这个码，不是双向技术凭据。这点在 `04-安全模型与已知局限.md` 里讲清了。

## 五、删除已存的 Bearer token

界面里输入新值覆盖即可。若要彻底删掉某个 agent 的 token：删掉本地数据目录 `tokens.json` 里对应 `agent_id` 的键，或直接删整个 `tokens.json`（会清空所有 agent 的 token）。

## 六、刷新与排错

- **刷新**：对每个 agent 逐个探活，更新状态列。
- 载入失败：多半是插件没正确加载或路由没起来，检查插件是否 enabled、web 服务是否重启过。
- 保存失败：看红字给的 error。常见是端点不是私有 IP、缺 `agent_id`、`agent_id` 重复。
