# 05 · 从接入到自动执行（部署实操，非插件核心能力）

> 先说清楚边界：**本插件只做「接入登记 + 诚实探活」，不派活、不自动回信。** 下面这份，是我们在真实环境里把已接入的 agent 真正驱动起来「自己领任务、自己用模型生成、产出回传共享板」的**外部部署方法**记录，供想做自动化的人参考——它不是插件自带功能，也不改变插件的能力边界。

## 关于文中的脚本与路径

文中提到的 `doubao_gen.mjs`、`relay_doubao_to_board.sh`、`desk_dispatch_mcp.py` 的 `do_work` 改动等，都是**作者在自己环境里的实现示例，不随本插件分发**；读者照此方法自建即可。以下 IP、主机名、路径均为作者环境示例，请按自己的环境替换。

## 一、思路：三条腿拼起来
- **A 确定性活**：agent 端常驻 worker 自动领任务、执行脚本、落盘。验收要**可复算 + 负对照**（停执行端→应无产出），不能只看 `status=done`。
- **B 脑力活（CDP 驱动）**：对端若是 Chromium 内核客户端（如豆包 `Doubao.exe`），带 `--remote-debugging-port` 重启后，用 CDP 从命令行驱动它模型真生成（输入→发送→抓回复），不碰 GUI、不截图。
- **收板器 relay**：agent 端落本地 outbox，dsh 侧常驻脚本每 15s 把新产出 scp 上共享板。（agent 端装不了 paramiko / 无法自己推板时，dsh 侧代搬。）

## 二、实测链路
```
dsh --dispatch(MCP,带Bearer)--> agent 收件箱 --> 常驻 worker 领活
   --> {确定性: 跑脚本 | 语义: CDP 驱动对端模型真写} --> 落 outbox 产出 + ack
   --> dsh 侧常驻 relay 每15s 搬上共享板 产出/ 回执/
```
实测：SCNet 确定性金丝雀 `Q0026`；豆包语义 `T-20261110-012`(日记)/`T-013`(诗)/`T-014`(随笔)——均全自动完成、产出与回执上共享板，全程无人点会话。

## 三、关键参数（复现要点）
- **豆包 CDP**：exe `C:\Users\<user>\AppData\Local\Doubao\Application\app\Doubao.exe`；`--remote-debugging-port=9333`；必须用**交互式计划任务（LogonType Interactive）在 session1** 重启（SSH 的 session0 够不到桌面）；`GET /json/list` 取 `url含 doubao-chat/chat` 的 page 的 `webSocketDebuggerUrl`；输入框 `div.ProseMirror[contenteditable=true]`，`Input.insertText` 输入、`Input.dispatchKeyEvent` Enter 发送；抓回复用 `document.body.innerText` 按 prompt 定位（**别用 class 猜**——推荐按钮 class 含 `suggest-message` 会被误抓）。
- **SCNet**：server 加 `wait` 长轮询（claim queued→doing 返回 task），装无模型 runner，落共享板用 `board.write`。
- **relay**：`relay_doubao_to_board.sh`，每 15s 扫 agent outbox 的 `*.reply.txt` / `*.ack.json` 推到共享板 `产出/`、`回执/`。

## 四、坑（务必看）
1. SSH 进的是 **session0**，`MainWindowHandle` 全 0，看不到也点不到 session1 的 GUI；操作桌面必须交互式计划任务在 session1 跑。**别用截图+坐标点 GUI**（会截到自己屏幕、白折腾）。
2. CDP 端口只 bind `127.0.0.1`，脚本须本机跑；node 24 自带全局 WebSocket。
3. 凭据占位符塞进双引号/heredoc 里**不会被替换**，要裸写赋给变量再落文件。
4. `setsid` 起的精简环境缺 PATH，脚本里要 `export PATH=...`，否则 sshpass 静默失败。
5. agent 端 pip 可能坏、装不了 paramiko → 推板走 dsh 侧 relay。
6. 抓回复别抓 `body.innerText` 末尾（那是侧边栏）；按 prompt 定位、截到"免费/推荐/新对话"之前。

## 五、局限（如实，不粉饰）
- relay 已改系统级 systemd（`Restart=always`、`enabled`），kill -9 当场验过自愈；对端另装隐藏守护盯 server 脚本 / MCP 端口 / 调试端口，掉线约 20s 内自愈。确定性 worker 那侧仍靠手动拉起、未做守护。**开机自启已布置但未重启机器实测**。
- 语义分支同步阻塞（等 CDP 生成 30–50s），量大需异步队列。
- 端点鉴权 / doing 租约 / 孤儿回收仍需补齐；SCNet 端点无鉴权是风险。
- 目前只落了「有 CDP 的豆包 + 纯确定性 SCNet」，其余 agent 要各自接。
- **这是部署实操记录，不是插件功能；插件仍只做接入与探活。**

## 补记：机器重启后要人工复活（实测）

AB 闭环**能跑，但不扛重启**。对端机器重启后，几个"零件"往往会散，需要人工拼回：图形客户端变成**不带调试参数的普通自启实例**（丢 `--remote-debugging-port`）、常驻 server 脚本可能被清理工具挪走（表现为端口直接连不上 / `can't open file`，不是"没自启"）、常驻 relay/runner 也可能掉。拼回后又恢复全自动闭环。

**重启后先查三样，缺哪个补哪个，别急着投任务**：① 对端 server 脚本还在不在原目录（可能被挪进回收目录）；② 调试端口在不在听（重开图形客户端要带调试参数、且须在交互式会话里跑）；③ MCP 端口是否 HTTP 200。

另实测：只有装了常驻 worker + 有 CDP/可执行体的 agent（确定性 worker / Chromium 内核客户端）能套 AB；**只有收件队列的（明写"只入队、不自动执行、只认显式 claim"）不成立**——投了任务也只是躺着，又一次印证「入队 ≠ 执行」。走共享文件板时，投件要用**绝对路径**（相对路径常报 553）。

踩坑：Windows `cmd` 的 `copy` 不认单引号路径，后面接 `& echo copied` 仍会打印 copied → **假绿**；用 `powershell Copy-Item -LiteralPath` 并当场 `Test-Path` + `Length` 验真。
